2026-11-15｜Goal 候选权限核对与两例小对照

结论：现有规则允许模型直接提议修订非权威候选，不要求用户另说“保存”。本次补充中性权限说明后，方向改变例真实 revise 并保存；只恢复 AMD 例未误改长期 Goal。单次结果不证明稳定性或因果。

一、规则／实际工具说明／实际用户原话并排核对

项目：候选提案权限
Host规则：GoalResearch.submit 校验当前注册输入、操作、当前 head、引用及预算，没有“用户必须说保存／再次确认”的条件。候选提交不同于正式 ActiveGoal 的 adopt/revise。
实际工具：description 明确为“Optional non-authoritative Goal Hypothesis research channel”，允许“changing/withdrawing a prior candidate”；回执只记录 candidate，不授予执行权限。
本例用户原话：“仍关注AI产业，但不再以寻找股票投资机会为目的，改为研究企业AI算力采购和部署风险。”
判断：足以供模型判断提议修订；是否真调用由模型选择。旧轮没有调用，不能说发生了 Host 拒绝。

项目：复盘后一轮的引用
Host规则：quote 必须是 CURRENT 注册用户输入中的原文片段；input_ids 可指向合法的原始用户输入。PersistentGoals 保留候选关联历史，当前同 Thread 的注册输入也在来源集合中。
实际工具：quote = “Exact substring of CURRENT registered user request”；input_ids = “Optional original user input IDs asserted as basis. Never model/summary IDs.”
实际输入：上一轮方向原话 input:23630a6c-b667-4c7f-bbba-386cb59b981a；当前复盘 input:8c55ccef-5527-4c56-8a25-7bb7979c0a2f：“把用户本轮原话和当前保存的 Goal 放在一起看。现在这份记录还准确吗？按你的判断处理。”
判断：上一轮方向原话仍可通过 input_ids 支撑语义；CURRENT quote 应摘自复盘。本例两条输入均在实际出站 retained_user_requests 中。CPU 原状态校验按该组合通过全部提交前检查，然后主动在写入前中止；没有制造 Native 调用、保存或回执。历史方向句不能直接代替 CURRENT quote，这是 CPU 反例，不是旧轮已发生的拒绝。

项目：正式 Goal 权限
Host规则：GoalIntegration.control 要求明确 Host 控制和 adopt 模式；研究 GoalResearch.control 禁止正式采纳或授权。
实际工具：candidate only；actual ActiveGoal remains null；无自动 Memory Admission。
判断：不需要把“候选可提议”解释为“模型能自行改变正式目标”。

二、实验
未找到同起点、仅澄清候选权限的完全同型对照；既有邀请／显式 revise 研究不替代本题。
A 直接复用上一轮常规流程的原始结果，不重跑；B 独立新 Thread 恢复相同真实 Goal checkpoint、相同选择历史，用户原话逐字一致。
唯一计划新增语义输入是一条 developer 说明：
“你可以按现有规则提议修订非权威候选，也可以保留原记录。”
没有指定哪例该改，没有提供标准候选，没有要求采用 revise，没有追加本轮用户“保存确认”，不修改工具 Schema 或 CURRENT 规则。
自然生成的 Thread/Input/Call IDs 不同；这不是严格逐字节随机 A/B，也不是同一次随机生成的反事实。
