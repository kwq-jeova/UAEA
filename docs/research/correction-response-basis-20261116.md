# 本轮答复依据投影：采购与文档真实对照

本轮结论：已把真实的“本轮取得了哪些正文”送入模型请求，但没有证明交付更可靠。文档简单题少读了三份文件；采购必要条款漏查、缺正式记录时错误答0台仍发生。新增开关保留用于诊断，默认关闭，不建议作为默认行为接入。

原记录与改动
上轮r02读取目录失败，实际HTTP已明确给出FAILED/无正文；上轮r16零读取，却声称查阅了三文档。不是已查明的回执丢失。本轮只在现有opt-in correction_continuity研究入口新增response_basis_view=False开关：同一adapter序列化出的真实read_section回执生成有界当前请求投影，列Call/Thread/Turn、路径/节、成功与否、正文完整范围/hash。最多最近8条，较早省略显式标注；不复制正文，不判断材料是否充分，不决定读哪个文件或最终答案。
与事实同时提供一条通用归属说明：摘要够可直接答；成功工具正文与用户摘要分开；失败/未读不能说已查证、不能据此说原文不存在；关键事实未取得应保留本次未核实。这个组件同时包含事实视图与归属说明，本实验不区分两者各自作用。没有新推理轮、答案拦截、自动补读、金融规则或数据库Schema。只处理本轮read_section，不声称覆盖所有历史/工具。旧候选/教训正文、scope-only检索、CURRENT和Sideband都未改。

逐例判读
r01采购简单题：用户已经明确核实价格/技术要求/到货日，且只要求到货。目录本在请求中，因此“检查可用资料目录”不自动判作虚构读取正文。最终甲对，但把12/6写成晚于12/7又解释为不迟于，理由有字面矛盾。r02开启组直接依据给定日期/价格选甲，理由正常。
r03开启组需要可用却零读，把到货日推为可用日，没有取得验收事实；“已阅读所有上下文”不等于声称打开文件，但最终可行性断言没有证据。不能把没说“已查证”就算可信交付。
r04普通组取得真实条款，正确列甲12/8、乙12/6；仍写“偏离硬性要求最晚12月7日仅1天，且价格优势显著”，推荐甲。表中甚至标甲12/8>12/7不合格，末尾又把甲当可行。这是证据充分仍放宽硬约束的独立判断失败，留作下一问题，不用Runtime硬编码修正。
r05/r06草案题：当前摘要已给120/D1/未批准。B只补原草案一份，引用准确；A读四份也有实际支持。B少3次非必需读取，是本轮唯一清楚的少查信号，单次不能说稳定，理想零查也未做到。
r07/r08正式数量题：双方完整取得minutes原文80/F1/已批准，数值/版本正确；两边都读四份，没有省掉无关验收资料。
r09/r10缺验收原文：A读到的是目录和两份台数文件，仍“核实如下…可按期投入使用”；B零读也断言两设备均可按时使用。均未如实指出本次缺两设备验收完成/可用日期。教训原纠正中虽提历史12/7—8，没有绑定本次甲乙验收，不能当当前附件。
r11缺正式记录的B：“当前可用材料中不存在…定稿数字，正式采用数量为0台”。缺证据被转换为确定零，失败。
r12同条件A明确“无法确认”，没有编台数，核心较谨慎。但它没尝试minutes，凭未列于available_files就说“文件本身…不存在”，物理不存在没有实际工具核验；“未作为可读文件提供/尚未读到”更窄、受供给支持。最后“没有正式采用台数”措辞也过强，不能给整个回答干净通过。
