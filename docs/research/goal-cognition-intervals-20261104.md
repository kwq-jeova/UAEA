# Dynamic Goal Cognition：认知轨迹、时间区间与可量化边界（2026-11-04）

结论：**研究可继续；“Goal波动”不宜作为一个单独、通用的数值指标。**
现有记录支持观察系统记录/供给/修改了什么，尚不足以估计真实用户Goal的连续轨迹、误差距离或建议效用。
本轮以理论、现有证据和极小测量反例为主，没有新增认知算法、Runtime模块、模型调用或权限机制。

## 1. 首先修正研究对象

**HYPOTHESIS / 推荐**：优先研究“有时间与来源依据的认知修订及其后果”，
将Goal波动作为若干现象的统称，不预设连续曲线、周期、吸引子、最终收敛或唯一正确Goal。

至少分别观察：
- 用户表达/合法承诺：当时明确要求什么，何时取消、替换或重新开始。
- UAEA解释：候选、竞争解释、工作理解及其依据如何变化。
- 条件与实施路径：资源、事实判断、可行办法如何变化。
- 正式状态：ActiveGoal、Workflow、授权的合法决定。
- 实际后果：模型回答、澄清、工具执行、建议与用户反馈。

这不是五个新模块，也不要求同一种数学模型描述全部变化。
可共用的是来源、时间、版本和依赖约束，而不是共享一个“波动分数”。

**CONFLICT**：
把一次标签/措辞变化直接等同于用户Goal改变；
把长期稳定等同于正确/最优；把快速修订等同于失败；
把解释的熵或Embedding距离等同于认知质量。

用户自己的Goal也未必有一个可被系统判定的绝对正误。
“目标错误”必须先说明参照：违反其明确约束、依赖错误世界事实、与其已声明价值不符，还是事后未获成功。
这些参照不能混用；即使路径无效，也不能据此未经授权替换用户目的。
后来的成功方向不能自动变成评价全部早期探索的唯一真值。

## 2. 用时间关系表达区间，暂不要求统一分段算法

### 2.1 同一个判断至少有三种时间问题

1. **记录/认识时间**：系统何时看到、产生或修改这个判断。
2. **所描述的适用时期**：它声称描述用户过去、现在还是将来的方向。
3. **使用与后果时间**：它何时被供给、被某次决定明确引用或形成了实际行动。

知道某条记录何时写入，不等于知道用户Goal何时开始。
后来用户说“我一直是这个意思”，允许系统修改对过去的解释；
不能把该修订写成系统从一开始就知道，也不能虚构用户在澄清时改变了Goal。

既有信息论专题§4.3已区分观察/记录/适用时间。
时间数据库的valid-time/transaction-time提供有用区分，但这里只借用语义，不建议建立新数据库。
参考：[Jensen / Snodgrass，Bitemporal Relation](https://experts.arizona.edu/en/publications/bitemporal-relation-2/)。

### 2.2 “形成”的开始不是一个必然唯一的时点

可区分可观察里程碑：
- 某个候选首次被记录；
- 原文第一次提供可审查的方向依据；
- 系统首次把它作为当前工作解释使用；
- Host正式采纳该Goal。

这些时点可以不同，现有数据也可能只覆盖其中部分。
它们不等于用户内心真正形成Goal的时点。
连续出现几次相关请求可以增加待研究线索，不自动越过形成阈值或Adoption。

终点也分别可能是明确取消、条件失效、解释被反驳、工作视图不再采用或正式状态暂停。
暂停不是永久取消，不再可见不是已结束，缺少新提及不是用户放弃。

### 2.3 边界可以未知、开放或部分有序

区间可以是“这次明确声明之后”“下一次合法替换之前”，不必先有精确秒数。
若只在时点2看到A、时点6看到B，在承认状态编码可比的前提下可知期间至少有一次变化；
不能证明只有一次，也不能恢复首次变化、反复回归或完整持续区间。
在开始前缺少记录时，起点保持未知；观察结束仍无修订时，终点保持未观测，而非无限持续。

对软件Host状态，完整且可信的变更账本可能给出精确的状态存续区间；
同样精度不能外推到用户私有Goal或模型内部信念。

相对、不完整的时间知识可借鉴区间逻辑，不必强制变成唯一时间点。
参考：[Allen，Maintaining Knowledge About Temporal Intervals](https://urresearch.rochester.edu/institutionalPublicationPublicView.action?institutionalItemId=10115&versionNumber=1)。
它不负责定义Goal语义，也不能为缺失记录补出端点。

### 2.4 多时间尺度与窗口

观察窗口应服务于研究问题，并报告：
- 使用了哪些原始来源、哪些Scope及版本；
- 其中哪些当时已知，哪些是后来才补得；
- 窗口外是否仍保留Host记录；
- 是否存在缺失、介入或被迫中断。

同一人可同时有数年方向、阶段项目和即时任务，因此不同Scope区间可以重叠；
不宜强制整段生活只处于一个Goal状态，或把时间线切成互斥阶段。
短窗口里的任务变化和长窗口里的方向保持并不矛盾。

评价“当时是否合理”只能用当时可知信息；
事后重建可用后续澄清，但必须保留“何时才修正认识”的历史。
把未来信息混入在线评价，会制造虚假的早期错误或准确性。
更长窗口也未必更好：旧解释可能失效，过时信息可能污染当前理解。

## 3. 当前能量化什么

| 候选量 | 必需条件与明确含义 | 当前边界 |
| --- | --- | --- |
| 记录/版本变更次数 | 对象、Scope、版本及观察机会一致 | 可计数，但不是语义变化幅度或质量 |
| 某记录的重复供给次数/跨度 | 同源身份明确、请求ID可区分、时间来源可比较 | 可以审计；不等于模型采用或错误持续 |
| 与明确要求不符的检查点数 | 事先规定参照及可比较判断单位，独立复核 | 可在限定任务中评价；自然长期Goal真值仍未知 |
| 纠正信息可用后首次合适修订的间隔 | 信息确已供给、目标判断可评价、时间/机会单位明确 | 无时间可报决策机会差；首次改对不等于持续恢复 |
| 修订后错误再现 | 后续有可比检查机会且参照未变 | 要同时报告后续观察量，不能把未观测当无再犯 |
| 已知下游引用/使用范围 | 可解析依赖、出站审计或决定引用 | 只能描述已知部分；可见/关联不证明因果 |
| 任务进展与交互负担 | 真实Observation、完成标准、追问/重做记录 | 可限定核验；不能用Turn Completed、满意措辞代替 |
| 实际建议价值/损失 | 用户目标、成本与后果评价标准，必要时对照 | 目前UNKNOWN，不能给默认权重或成功概率 |

**暂不可可靠计算**：
真实Goal的通用距离、变化幅度、错误持续总时长、稳定最优概率、有效bit、真实Goal Entropy、
普遍适用的认知置信度、主动建议成功率及总效用。

文本相似、Token数和修订次数不是这些量的替代品。
如果日后定义结构化语义差异，必须先规定哪些属性可比、哪些差异重要；
不能因为集合或向量距离容易计算，就赋予它通用Goal意义。

**建议保留评价向量，不立即做总分**：
要求一致性、纠正响应、后续再现、覆盖/弃答、任务结果、用户负担、权威违规和影响可恢复性分别记录。
没有外部偏好时，一方更少误解但更多打扰，另一方相反，可能本来就不可直接排序。
硬性授权违规不能用其他质量分数补偿。

“始终UNKNOWN”可能没有错误断言，却也没有帮助。
必须并列观察任务覆盖与实际价值，否则零误报会成为一种无用但高分的策略。

## 4. 错误区间、恢复与影响范围

恢复至少可能指：
- 撤回错误解释；
- 后续回答不再使用它；
- 依赖它的建议/状态得到重新评价；
- 已发生的后果被纠正或补救。

这些不是同一个终点。改了摘要不等于消除了影响；
修正软件状态也不能撤回已经发布的错误建议或不可逆行动。

应分别记录：
- 错误或不充分支持最早可核验的位置；
- 反证/澄清首次实际可用的位置；
- 工作解释修订的位置；
- 后续可比检查中的再现；
- 已知引用、建议、决定、实际行动及补救。

缺少参照时，应称“争议解释/未建立支持”，不直接称已证实错误。
错误只在几个检查点出现，不足以填满整段时间为持续错误。
观察结束前没有恢复，也不能填入任意超时当恢复时间。
系统因资源、Context或任务中断而停下时，还应注明中断原因；观察长短可能影响结果。

影响须区分范围、后果与可恢复性：
候选内部保留、进入模型Context、进入用户回答、影响工具选择、改变正式状态和产生实际行动，各有不同证据要求。
正式Goal/权限未变不等于没有认知或用户影响；
反过来，摘要进入Context也不能证明它导致了后续回答错误。
R0/R1中的来源关联、asserted_supports和available_in_context不能自动变为因果关系。

## 5. 真实记录的最小核查

### 5.1 同源摘要的供给区间：可测，但不是Goal错误区间

原运行：interactive-32768-20261102-065220。

同一完整摘要可在两个出站审计请求中定位：

| 位置 | 北京时间（Asia/Shanghai） | 结果 |
| --- | --- | --- |
| model-http-audit.jsonl:31 | 2026-11-02 15:12:50.015 | 对应transport_result为HTTP200 |
| model-http-audit.jsonl:33 | 2026-11-02 15:13:54.688 | 对应transport_result为HTTP200 |

请求快照为脱敏审计，明确不是字节级Wire或模型理解证明；
对应响应也标明model_understanding=not_established。
两次请求仍只有同一派生摘要来源，不能算两份独立外部支持。

实际Goal是否变化、模型是否相信该断言、完整错误起点/修正终点、对答案的因果影响均UNKNOWN。
证据与Locator：real-compaction-window.json、source-manifest.json。

### 5.2 候选来源错误拒绝：顺序可查，延迟未知

原运行：goal-compat-active-20261102T124823Z/bolt/harness。
- app-server-events.jsonl:437：模型输出；

详细字段见real-rejection-window.json。

### 5.3 不把独立试验拼成恢复轨迹

旧Bolt不同API实验臂、不同提示或重跑中的正确/错误答案，
即使按执行先后排序，也不能自动成为同一认知状态的恢复过程。
Longitudinal原型的30/30依赖预定义语义判断；不能当成自然长期目标曲线。
495项窗口检查只证明保留Host账本时的本地视图一致，不是模型实际使用或真实Compaction恢复验收。

## 6. 极小合成反例：否定“波动即质量”的简单假设

没有开发新认知算法，仅用冻结的离散任务参照构造四条6检查点轨迹。
good/bad/unknown是预定义受控任务标记，不是人类唯一真实Goal标签。

| 轨迹 | 标签变化 | 不符参照输出 | 符合参照输出 | 弃答 |
| --- | --- | --- | --- | --- |
| 稳定但错误 | 0 | 6 | 0 | 0 |
| 后续修正 | 1 | 2 | 4 | 0 |
| 反复来回 | 5 | 3 | 3 | 0 |
| 始终未知 | 0 | 0 | 0 | 6 |

这足以否定“变化越少越好”“变化越多越好”和“零错误断言就足够好”作为通用评价规则。
它不证明人类认知规律，也不证明某个UAEA算法更好。

修正轨迹和来回轨迹在纠正信息可用后的第一个合适检查点相同；
后者后来又出现两次错误，因此“首次修正快”不等于恢复稳定。

另有两条完整路径在检查点2同为bad、检查点6同为good，
中间分别为一次切换和多次来回。稀疏探针不能唯一确定变化边界或首次恢复。
不能在没有观测/保持假设时，把两个点插成一条真实连续曲线。

这些只是测量定义的反例，不是新的模型能力Benchmark。
原文、参照与分析在counterexamples.json / measurement-counterexamples.json。
没有加权总分、概率、熵或“有效信息”计算。

## 7. 理论工具的取舍

| 理论 | 可以借鉴 | 尚缺前提及误用边界 |
| --- | --- | --- |
| 区间逻辑与双时间语义 | 部分有序、重叠、未知端点；描述时期与记录时期分开 | 不自动识别Goal含义或补出缺失边界 |
| Bayesian Filtering / 部分可观测系统 | 区分潜在对象与观察，理解系统认知不等于真实状态 | 缺少可靠观测模型、动态假设与校准数据；不等于应新建POMDP控制器 |
| Change Point Detection | 检测明确定义观测序列的分布变化，区分在线与事后研究 | 编码器/模型升级也能造成变化，不能直接命名为用户Goal改变 |
| Shannon / MDL | 变量、概率/编码模型成立后评价不确定性或预测解释 | 当前没有可靠语义单位与估计基础，重复/候选数不能充当bit或熵 |
| 决策理论与预测评分 | 将具体预测或建议与可观察结果/成本联系 | 没有分布、目标结果、效用或独立参照时不能填入建议价值分数 |

[BOCPD原论文](https://arxiv.org/abs/0710.3742)研究的是生成参数变化，并有其分段假设；
这不建立UAEA的Goal转移/观测概率。
[部分可观测规划原论文](https://www.sciencedirect.com/science/article/pii/S000437029800023X)提供问题视角，
不意味着可直接用一个隐状态代表所有人的目标，也不授权复制执行控制器。
[Proper Scoring Rules](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)
评价概率预测需要分布和实现的观察，不能把模型自评Confidence当校准概率。

以上核对公开摘要/出版记录，不是算法复现；部分原PDF受大小、访问或超时限制。
本轮没有估计这些模型的参数，也不宣称证明任何理论已经适用于UAEA。
多Goal、多Scope、观察选择与模型建议会共同影响后续交互；
将用户反馈当完全外生、独立样本也需要额外论证。

## 8. 无绝对Goal真值时，如何评价

建议按评价时点分开问：
- 是否忠实保留了用户当时的明确要求与合法修订？
- 当时证据是否足以支持该解释，是否承认其他合理解释？
- 新信息实际可用后，是否修正不再成立的解释？
- 是否把自己旧判断伪造成用户历史？
- 是否在条件改变时调整路径，而没有擅改目的？
- 是否保留未知且仍能处理不依赖长期Goal的当前任务？
- 是否真实推进了可核验任务，增加或减少了用户负担？

形式与权限指标可较多依靠确定性记录；
语义支持、合适的弃答、建议质量通常还需要可审查任务条件、独立语义判断或用户反馈。
用户喜好与长期价值不能普遍由测试脚本代替；满意度也不能证明世界事实真实。

未来观察可用于检验事先明确的预测，但“预测用户下一句话”不是最终目标。
后续用户行为可能受系统建议影响，预测命中也不能直接证明理解了一个原本独立存在的Goal。
必须说明系统介入与观察选择，不能用自己产生的建议/摘要验证自身认知。

## 9. 现有架构适用性

**VERIFIED（限定）**：
Canonical、Observation、RuntimeObjectStore、G0/G1控制与R0/R1局部引用，
足以开始研究带来源、版本、Scope的轨迹，不需新Information Pool。
Semantic Interpretation记录semantic_correctness=not_established，与Authority Validation分开是必要边界。

**UNKNOWN / 实际缺口**：
适用区间通常未知；部分控制/拒绝缺时间；跨流时钟、跨Session身份与完整旧版本解析不足；
语义反证是否有效、原始依据是否被实际使用及影响链不完整；
自然长期用户Goal与建议效用缺独立参照。

这些缺口应限定具体测量，不能通过假定“所有时间都是UTC”“created_at就是Goal起点”或“引用即影响”填补。
本轮也未审计所有日志时钟，不进行全项目时间体系重构。

**HYPOTHESIS**：
沿用现有对象和原始日志引用，增加研究侧的时间/判据说明就足以开展下一项限定实验。
是否需要收敛正式时间或评价记录契约，须由该实验暴露的实际阻碍决定。
不改变Phase-1/Harness执行所有权，不改Goal Adoption、Memory或运行入口。

## 10. 最值得先验证的一个假设

**HYPOTHESIS**：
在共同的原始证据和同一纠正信息可用条件下，保留解释依据及所描述时期，
能否减少后续对旧错误解释的使用，同时不阻碍用户明确修订？

建议最小实验：
1. 选取可独立核验的多轮任务，固定当前要求、可接受解释范围与用户明确修订点。
2. 固定同一初始错误、纠正证据、工具权限、Backend和观察机会；不以用户未来选择倒写早期真值。
3. 比较公平简单历史状态与携带来源/适用区间的认知视图；两者都允许合法修订与UNKNOWN。
4. 分别覆盖“纠正误解”“用户确实改目标”“条件改变、目的不变”，避免把三者用同一标签掩盖。
5. 记录纠正证据供给后错误再现、虚假历史、合法修订受阻、必要任务完成、额外追问/重做；
   不先规定Goal必须收敛。
6. 观察窗口不同、无关消息增加、同源重复、同义改写或模型版本更换时，检查评价是否仍有相同语义。

**否定条件**：
若在相同信息和可比预算下，额外区间表示没有改善这些终点，或增加过度弃答、打扰和迟滞，
应接受简单历史足够，不据此继续扩建模型。
若真实来源不足以建立参照或端点，就只能报告UNKNOWN，不能靠模型自评生成真值。
若不同错误/价值维度存在取舍，没有用户偏好时不强行选出“最优”模型。

当前只提出方案，没有执行该效益实验或调用新模型。
最小前提是少量可靠评价锚点、明确的数据可用时点和真实后果记录，
不是完整信息池、全局Goal真值或更复杂的熵公式。
