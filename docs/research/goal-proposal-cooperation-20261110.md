## 1. 独立设计判断

现有 Sideband 原生调用本来就同时表达结构化候选和显式提交意图，因此协同不必是第二个推理循环。
本研究先检验“区分判断与提交、明确利用真实回执”是否有可观察收益，不假设需要新接口或维护引擎。

| 条件 | 共同种子后机制 | 状态边界 |
| --- | --- | --- |
| A | 原有 Goal Sideband | 只有真实工具调用可提交 |
| B | 可选的完整 final JSON 认知判断 | 不提交；研究条件拒绝后续 Goal 工具提交，普通文件工具照常 |
| C | 可选结构化判断 + 原有 Sideband 显式提交 | 同一次原生工具调用已含提案与提交意图，无需事前评估调用或强制第二次推理 |
| H | Relevant History | 无 Goal 通道，只用原始历史与同一资料工具 |

B 是设计上的只评估条件，不能用其零提交率证明接口差。
本轮的结构化判断采用已协商 final envelope，**不是 API 强约束 structured output**。
不强制每轮生成候选或评估；普通回答不抽取入库，不自动补发工具调用。
每个评估的 submit_intent 只是模型声明；候选变化必须由原生调用、Host Journal 和出站版本证明。

最终评估在同轮工具之后才可见，可能是回顾性解释，不证明隐藏思考先判断再行动。
若 C 已先完成修订，最终 NO_CHANGE 也可能指不再需要额外版本，不能机械当错。
匹配字段只比较相同 payload；没有 exact match 不等于没有其他真实提交，须结合实际版本列表。

## 2. 实现范围与确定性边界

scripts/research/goal_cooperation.py 复用 ProposalApp、GoalResearch、原始动态工具 schema/验证与投影。
共同种子阶段各条件的上下文和工具接口相同；种子真实形成后才激活 A/B/C 的研究说明。
assessment 只写原有研究 Journal，不新增 RuntimeObject 类型、数据层或权威。
模型评估内容进入 untrusted 块，应用块只保留可确定的事件/提交引用。

NO_CHANGE/FORM/REFINE/REVISE/WITHDRAW/UNKNOWN 为研究判断，非正式状态。
Quote 及已知父引用可做结构检查，但不是语义支持证明，也不是完整提交资格判断。
真正 Goal 工具提交继续使用原始当前输入、父版本、来源与权限边界。
冻结前110项、收尾112项离线回归（原96+新增16）通过，覆盖禁止意图自动提交、B模式限制、C单调用提交、
原生来源、普通文字不提案、旧版本保留、错误评估不撤销真实提交及不可信投影。
收尾增加真实用户input ID误作Evidence的反例：拒绝后，调用者主动清空evidence_ids的新提案可通过；纯CPU，不替模型补发，不计真实恢复成功。\n收尾另发现本轮B研究包装器在阶段切换后误拒绝已提交种子的同Call ID回执重放。
一条反例先失败；现仅让已提交身份进入原有幂等验证，B仍拒绝新提交，同ID异内容仍拒绝。
这是研究包装器的局部状态一致性修正，不改基础验证/权限。该分支真实会话未触发；
执行bundle及原结果保持原版，修正后仅CPU回归，未重跑模型。replay-red.log及前后源码保留。
这些测试不证明 Goal 语义质量。

## 4. 七轮固定脚本与公平性

T1显式建立给定干净种子；T2取消子任务；T3改变资源/Path，长期目的明确不变；
T4用户明确替换长期方向，无额外评估邀请；T5邀请判断但不指定操作；
T6要求实际提交（已有正确候选则不重复，B如实报告限制）；
T7从适用版本中选读一份资料，依据正文提出验证及反证，并准确说明 Host 状态。

所有原始用户文本、资料字节、模型、域工具权限和Context预算一致。
三种机制在共同种子后才不同；B有意禁止提交，C增加协同说明与可选判断格式。
固定顺序、单个非金融脚本、生成历史、参数纠错机会、额外上下文Token都须报告。
不能把某个组的较低Token数、仅选对资料名称或偶然多调用当认知收益。
首次阶段与统一供给阶段分开，不混算为随机公平对照；补跑非按下游认知成绩选择。

### 5.2 四个环节的判别性失败

**A：理解与工具选择分开。**
模型能指出旧文档助手候选与项目归档方向不符，
却在T6将 active_goal_adoption_disabled=true 解释为“不允许提交/修订候选”。
没有实际提交，所以不存在本轮Host拒绝修订的证据。
这是可观察的模型权限语义误读；不能从其自述推断唯一内部原因，
也不能将其解释当成Runtime真的关闭了候选工具。

**C：语义提案合理，但引用类型错误、恢复未成功。**
T6原生Call ID：chatcmpl-tool-b0db9d3833fa8165；operation实际为 revise，
父ID为上述C种子，hypothesis是：
> 研究可验证的项目归档，保留来源版本和原始记录，并追查相互矛盾的资料。

它概括了原始用户目的，没有复制操作指令；当前Quote及父版本合理。
但把真实用户输入ID input:5e8c0643-fa62-4dde-80a8-ae2f64533051 同时填进
input_ids 与 evidence_ids。前者是合法原始用户引用，后者只接受Capability Observation。
这不是“该ID完全不存在”：reference-kind-case.json可解析到原始脚本T6；
T6前尚无域工具Observation。合法输入来源不能冒充执行观察。

Host明确回传 Evidence must reference actual Capability Observation，保持旧版本；
没有自动改字段、忽略检查或扩大权限。
模型最后承认未更新，状态结果基本诚实，但将实际revise称为maintain，
又把引用错误泛化为“目前仅能评估、不能提交修订”。它没有采用合法参数纠正。
成功传输的C条件明确允许原生Goal工具，context-mode-checks.json证明未错投成B。
这是**正确目的解释/提案表达 → 实际尝试 → 合法拒绝 → 反馈语义误读 → 无修正**，
不是成功的认知维护闭环，也不是已证明的Runtime存储或权限Bug。

**B：只评估的结果合理，理由仍需区分。**
模型认识到旧候选不适用，正确保留Host实际状态，并表示研究条件不提交。
未实际触发后续Goal工具，因此B的物理拒绝闭环只有离线测试证据。
它也会引用“不可自动采纳”的标志解释限制，不能据此证明理解了两个权限对象的区别。

## 6. 研究边界

本轮不计算概率、熵、MDL或建议成功率，不测试长期记忆收益。
Source link ≠ semantic support ≠ truth ≠ authority；保持相同的非权威候选定位。
空评估不能通过 all([]) 获得认知PASS；完整格式/回执也不能替代后续实际行为。
如果仍不足以支持新架构，保留现有 Sideband 与 UNKNOWN，停止扩大研究。

## 7. 架构建议与停止点

**不建议新增协同层，也不替换 Sideband。** 原工具已经同时承载结构化候选和显式提交，
C增加说明与可选视图，本轮没有形成新版本或实际决策增益，不能因多了一次尝试就工程化。

没有证据要求修改Phase-1、Source分类、Goal/Memory采纳或放宽引用校验。
用户输入应作为input_ids，不能为了让提案通过而作为Capability Evidence放行。
未验证解释继续可保留为研究历史，不成为可信事实或正式Goal。

若后续继续，最小问题应转为**可替换提案者是否理解候选提交/正式采纳、输入ID/工具Observation ID的类型区别，
并能依据已明确的错误反馈纠正一次真实提案**。保持同一现有工具，不再重复整套七轮试验、
增加认知状态字段或第二个审核循环。对错误作用域的确定性表达可单独审查，但本轮没有证明必须改正式契约，
更不能把更详细反馈假定为模型必然使用。

本轮到此停止，提交架构评审；不要求人工长会话。Memory仍Research Reserved。
